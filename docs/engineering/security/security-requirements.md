# AayurFace — Security Architecture Specification
## Formal Security Requirements Specification

**Phase:** Phase 03 — Enterprise Security, Privacy, Threat Modeling & AI Safety Architecture  
**Date:** 2026-09-03  
**Status:** FORMAL ARCHITECTURAL SPECIFICATION (Target Design; Implementation Pending)  
**Authority:** Principal Security Architect, Requirements Engineer, Compliance Lead  

---

### 1. Requirements Framework

Every security requirement establishes an unambiguous architectural contract, addresses specific STRIDE threats, and defines objective verification methods.

---

### 2. Formal Security Requirements Inventory

| Requirement ID | Security Requirement Statement | Rationale | Priority | Threat Addressed | Target Control Mechanism | Verification Method | Status |
|---|---|---|---|---|---|---|---|
| **SEC-AUTH-001** | All protected API routes must derive user identity exclusively from cryptographically verified RS256 JWT claims (`auth.uid()`). Any client-supplied `userId` parameter in request bodies or query strings must be ignored or strictly validated against `auth.uid()`. | Prevents identity spoofing and unauthorized cross-tenant impersonation. | **CRITICAL** | TH-01, TH-18, AC-SEC-002 | Supabase Auth JWT verification middleware at Edge Gateway. | Integration test verifying forged or mismatched body `userId` returns HTTP 403. | Target Control |
| **SEC-AUTH-002** | User passwords must never be stored in plain text and must be hashed using bcrypt (work factor $\ge 10$) or Argon2id prior to persistence. | Neutralizes credential exposure in the event of database snapshot compromise. | **CRITICAL** | TH-02 | PostgreSQL `pgcrypto` / Supabase Auth managed bcrypt. | Database inspection asserting all password columns contain valid bcrypt strings. | Target Control |
| **SEC-AUTHZ-001** | The platform must enforce multi-tier authorization (RBAC + Resource Ownership) across all endpoints. Non-admin roles must be physically barred from administrative operations. | Enforces least privilege and prevents privilege escalation. | **HIGH** | TH-30, TH-31, AC-SEC-006 | Edge API role-check middleware verifying `app_metadata.role`. | Automated fuzzing verifying consumer JWTs cannot invoke `/api/v1/admin/*`. | Target Control |
| **SEC-AUTHZ-002** | Unauthorized requests for existing user-owned resources must return HTTP 404 Not Found rather than HTTP 403 Forbidden. | Prevents resource UUID enumeration and targeted tenant reconnaissance. | **HIGH** | TH-18, AC-SEC-001 | Application service error handling masking unauthorized resources. | Integration test verifying User A requesting User B's scan UUID receives HTTP 404. | Target Control |
| **SEC-RLS-001** | 100% of user-owned sensitive relational tables must have PostgreSQL Row-Level Security enabled with atomic scalar policies (`USING (auth.uid() = user_id)`). | Guarantees multi-tenant multi-tenancy at the database engine kernel level. | **CRITICAL** | TH-06, TH-18, TH-42 | PostgreSQL `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`. | Automated SQL fuzzing asserting cross-tenant SELECT returns exactly 0 rows. | Target Control |
| **SEC-STORAGE-001**| The biometric image storage bucket (`facial-captures`) must permanently disable public read access and permit ingestion exclusively via short-lived HMAC-signed URLs (Proposed 15m TTL). | Eliminates public image exposure and unauthorized image enumeration. | **CRITICAL** | TH-05, TH-17 | Private S3 bucket configuration + Edge Function signed URL generator. | Direct unauthenticated HTTP GET to bucket returns HTTP 403 Forbidden. | Target Control |
| **SEC-STORAGE-002**| The system must support immediate hard-purging of raw facial captures post-feature extraction (DEC-004), storing only derived numerical vectors (`VisualObservations`). | Enforces biometric data minimization and eliminates long-term biometric liabilities. | **HIGH** | TH-17, TH-24 | Automated S3 `DeleteObject` trigger in analysis orchestrator. | S3 storage audit verifying raw capture file is deleted post-extraction. | Target Control |
| **SEC-PRIV-001** | Consent must be collected unbundled with independent toggles for biometric processing, history storage, and research sharing, and recorded in an immutable `consents` table. | Supports applicable data-protection laws (including DPDP Act 2023 principles; legal review required). | **CRITICAL** | TH-13 | Multi-step onboarding consent modal + append-only database table. | Verification that declining research sharing still permits core scanning. | Target Control |
| **SEC-PRIV-002** | Account deletion requests must trigger an asynchronous cascading hard-purge permanently deleting all user records, routines, history, and S3 images within 24 hours. | Enforces user right to erasure and prevents orphaned biometric retention. | **CRITICAL** | TH-14, TH-47 | Coordinated multi-service deletion worker with WORM tombstone logging. | Post-deletion forensic query asserting zero records remain in DB or S3. | Target Control |
| **SEC-AI-001** | Foundation models must operate inside an isolated privilege enclave with zero direct database write permissions and zero access to platform secrets. | Prevents model jailbreaks from compromising backend infrastructure. | **CRITICAL** | TH-32 | Stateless API invocation with zero tools/database connection access. | Architectural review confirming OpenAI client lacks DB connection keys. | Target Control |
| **SEC-AI-002** | 100% of AI analysis responses must pass strict Zod schema validation adhering to a pre-defined contract. Malformed or uncited outputs must fail closed. | Prevents malformed JSON or hallucinatory data from reaching the presentation layer. | **HIGH** | TH-38, AC-SEC-010 | Post-inference Zod schema parser with safe fallback handler. | Unit test passing invalid JSON asserts system serves verified fallback notice. | Target Control |
| **SEC-AI-003** | AI outputs must be deterministically scanned for medical diagnostic and prescription pharmaceutical keywords before presentation; violations must be scrubbed or dropped. | Enforces strict non-diagnostic boundary (`BR-AI-001`) and prevents illegal medical claims. | **CRITICAL** | TH-49, AC-SEC-004 | Post-inference regex safety filter scanning for prohibited drug/disease terms. | Adversarial prompt test asserting medical keywords are blocked. | Target Control |
| **SEC-RAG-001** | Classical Ayurvedic literature chunks must be ingested through an authenticated admin workflow with multi-expert sign-off and stored in a read-only table. | Prevents semantic knowledge poisoning and insertion of dangerous formulations. | **HIGH** | TH-10, AC-SEC-005 | PostgreSQL RLS policy restricting `knowledge_chunks` writes to `role: admin`. | Test asserting standard user JWT cannot execute INSERT on knowledge table. | Target Control |
| **SEC-RAG-002** | Semantic vector search over classical texts must enforce a minimum cosine similarity threshold ($\ge 0.75$) and match count ($\ge 2$) before invoking generative herbal synthesis. | Eliminates ungrounded generative hallucinations when literature does not match. | **HIGH** | TH-38 | Runtime cosine distance gate in RAG retrieval service. | Querying irrelevant term asserts generative herb synthesis is aborted. | Target Control |
| **SEC-CV-001** | The client SPA must execute an ephemeral WebAssembly landmark gateway verifying face count, centering, illumination, and blur before allowing image upload. | Prevents non-human, degraded, or spoofed images from consuming backend resources. | **HIGH** | TH-07, TH-50 | MediaPipe FaceMesh Wasm finite state machine in browser RAM. | Boundary test verifying dark or multi-face camera feeds disable capture button. | Target Control |
| **SEC-VOICE-001** | Voice assistant interactions must utilize local browser Web Speech APIs without transmitting raw audio to servers, and must be barred from executing destructive actions. | Protects audio privacy and prevents spoken command privilege escalation. | **MEDIUM** | TH-43, TH-44, AC-SEC-009 | Ephemeral browser transcription + voice command routing allowlist. | Voice command attempting account deletion is blocked with confirmation tap mandate.| Target Control |
| **SEC-ADMIN-001**| Administrative personnel must authenticate using hardware-backed Multi-Factor Authentication (WebAuthn/FIDO2) and have all actions recorded in an immutable WORM audit log. | Protects against administrative account takeover and insider data browsing. | **CRITICAL** | TH-15, TH-46 | WebAuthn enforcement on admin routes + WORM audit event logger. | Test asserting admin login without FIDO2 challenge is rejected. | Target Control |
| **SEC-RESEARCH-001**| Research annotators must access datasets through a double-blind, de-identified enclave stripped of user names, emails, and full face imagery. | Prevents subject re-identification and eliminates annotator bias. | **HIGH** | TH-33, TH-52 | Dedicated research schema + masked ROI vector presentation. | Re-identification vulnerability review of research export schemas. | Target Control |
| **SEC-OBS-001** | Centralized application loggers must enforce automated regex scrubbing intercepting passwords, tokens, base64 images, and PII prior to serialization. | Prevents accidental credential and biometric leakage into APM and SIEM logs. | **HIGH** | TH-19, TH-24 | Central logger sanitizer interceptor pipeline. | Unit test passing mock password and base64 string asserts `[REDACTED]` replacement.| Target Control |
| **SEC-INFRA-001**| Production Edge Functions must enforce a strict CORS origin whitelist (`https://app.aayurface.in`); wildcard `*` CORS must be permanently disabled. | Prevents cross-origin authenticated data theft from malicious phishing domains. | **HIGH** | TH-35 | Edge Function CORS configuration middleware. | Pre-flight OPTIONS request from untrusted origin asserts missing CORS headers. | Target Control |
| **SEC-INFRA-002**| The platform must enforce rate-limiting middleware on analysis endpoints enforcing a proposed baseline of 5 analyses per user per hour (DEC-006). | Neutralizes denial-of-wallet attacks and protects OpenAI API billing limits. | **HIGH** | TH-25, AC-SEC-007 | In-memory / Redis sliding window rate-limiting middleware. | Rapid script firing 10 calls asserts 6th call receives HTTP 429 Too Many Requests. | Target Control |
